# HireLens — User Research & Prototype Testing Protocol

> **CRITICAL COMPLIANCE NOTICE**:
> In accordance with strict program evaluation integrity guidelines for **Project Better Tomorrow**, **NO FABRICATED RESEARCH DATA, QUOTES, PARTICIPANT DEMOGRAPHICS, OR TESTING METRICS ARE PERMITTED IN THIS REPOSITORY**.
> 
> All files in this directory are structured standardized templates. They contain explicitly marked `TODO (real data required)` placeholders and must be filled in exclusively with raw notes, recordings, and validated observations gathered from genuine human recruitment practitioners.

---

## Directory Contents

1. [`discovery-interview-template.md`](discovery-interview-template.md): Qualitative discovery interview guide for hiring managers and recruiters to understand resume screening bottlenecks, hallucination risks, and compliance hurdles.
2. [`prototype-test-protocol.md`](prototype-test-protocol.md): Usability and task efficiency testing script (measuring baseline resume review duration vs. HireLens evidence-guided screening).
3. [`feedback-log.md`](feedback-log.md): Structured tabular log capturing raw feedback from each authenticated participant session.
4. [`iteration-log.md`](iteration-log.md): Traceability matrix connecting observed tester difficulties to specific code improvements and commit hashes.

## Evidence Collection Standards
- **Informed Consent**: Every participant must consent in writing to anonymized note-taking prior to beginning a session.
- **Participant Anonymity**: Store participant identifiers using synthetic tokens (e.g. `REC-01`, `REC-02`) and do not commit personally identifiable contact information into git.
- **Raw Evidence Retention**: Keep original audio recordings, screen captures, or handwritten notes in secure local project storage as primary audit evidence.
